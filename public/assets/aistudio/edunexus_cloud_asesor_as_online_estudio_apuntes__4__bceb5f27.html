    Preguntas Frecuentes de la Plataforma (FAQ)
    
        
    
          
            1. ¿Cómo funciona la validación obligatoria de documento para ser Asesor?
            +
          
          
    
            Cualquier cuenta guardada puede alternar entre Estudiante y Asesor, pero antes de habilitar el Portal Asesor o publicar un perfil docente, el sistema exige adjuntar un documento acreditador (Título SUNEDU, Constancia Docente Universitaria o Diploma de Posgrado). Una vez validado, queda vinculado permanentemente a tu cuenta.
          
    
        
    

        
    
          
            2. ¿Para qué sirven los 50 Puntos de Bono (EduPoints) y cómo se pagan las asesorías?
            +
          
          
    
            Los 50 Pts de bienvenida son puntos de fidelidad canjeables por packs de solucionarios e insignias dentro de la Billetera. Las asesorías personalizadas tienen un costo monetario real por hora (en USD o Soles PEN) que se abona mediante Yape/Plin, tarjeta o recarga de Saldo Real.
          
    
        
    

        
    
          
            3. ¿Cómo funcionan los Asesores IA y los apuntes en la Pizarra Digital?
            +
          
          
    
            Cada asesor está conectado a un servidor de IA conversacional con aislamiento de especialidad. Cuando conversas con un asesor en el Aula Virtual o desde el botón ✨ Gemini IA, te responde como en un chat natural y transcribe automáticamente las fórmulas y el esquema visual en la Pizarra Digital.

          📜 Script SQL para el Editor SQL de Supabase (Tablas + Realtime + Políticas RLS):
          
        
    
        
    -- 1. Tabla de Perfiles de Usuario (Sincronizada con Auth / Cuentas)
create table if not exists public.profiles (
  id text primary key,
  name text not null,
  email text unique not null,
  role text default 'Estudiante',
  uni text default 'Universidad',
  is_verified_tutor boolean default false,
  verified_doc_name text default '',
  created_at timestamptz default now()
);

-- 2. Tabla de Publicaciones en Tiempo Real (Social Feed)
create table if not exists public.social_posts (
  id text primary key,
  author_id text not null,
  author_name text not null,
  author_email text not null,
  author_role text default 'Estudiante',
  category text default 'Consulta Académica',
  content text not null,
  likes_user_ids jsonb default '[]'::jsonb,
  comments jsonb default '[]'::jsonb,
  created_at timestamptz default now()
);

-- 3. Tabla de Mensajes Directos en Tiempo Real (DM)
create table if not exists public.direct_messages (
  id text primary key,
  sender_id text not null,
  sender_name text not null,
  recipient_email text not null,
  message text not null,
  created_at timestamptz default now()
);

-- 4. Habilitar Seguridad a Nivel de Filas (RLS) y Políticas de Acceso
alter table public.profiles enable row level security;
alter table public.social_posts enable row level security;
alter table public.direct_messages enable row level security;

create policy "Lectura publica de perfiles" on public.profiles for select using (true);
create policy "Escritura de perfiles" on public.profiles for all using (true) with check (true);
create policy "Lectura publica de posts" on public.social_posts for select using (true);
create policy "Creacion y actualizacion de posts" on public.social_posts for all using (true) with check (true);
create policy "Acceso a mensajes directos" on public.direct_messages for all using (true) with check (true);

-- 5. Activar replicación en vivo (Supabase Realtime)
alter publication supabase_realtime add table public.profiles;
alter publication supabase_realtime add table public.social_posts;
alter publication supabase_realtime add table public.direct_messages;
